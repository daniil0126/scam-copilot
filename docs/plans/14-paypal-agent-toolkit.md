# 14. PayPal Agent Toolkit в чате (сжатый план: сегодня 01.11 и завтра 02.11)

**Цель:** чат отвечает на вопросы о счетах аккаунта по свежим данным PayPal, которые модель запрашивает инструментами Toolkit. Только чтение, только Sandbox. Итоговый риск считают правила, не модель. **Закончить и влить к вечеру 02.11**; 03.11 только видео и исправления.

## Объём (урезан)
Входит: 2 инструмента (`list_invoices`, `get_invoice`) через `@paypal/mcp`, цикл вызова инструментов, защита результатов, подпись «Used: …» в чате, 8 проверочных вопросов.
Не входит: локальные инструменты, подсказки вопросов в UI, пересчёт риска моделью, любые записывающие инструменты, транзакции и споры.
**Отсечка:** если к 14:00 завтра (02.11) агент не работает на живой модели, остаётся вариант B (те же два чтения поверх `paypal.py`, без слов «Toolkit» в описании) или план снимается, чат остаётся прежним.

## Общий интерфейс (договариваемся сейчас, чтобы работать параллельно)
Даниил отдаёт Руслану модуль `app/paypal_mcp.py`:
```python
async def list_tools() -> list[dict]            # [{"name","description","inputSchema"}], ровно list_invoices и get_invoice
async def call_tool(name: str, args: dict) -> dict   # сырой JSON PayPal; ошибка -> исключение McpUnavailable
def available() -> bool                          # False: нет Node, процесс не поднялся, нет ключей
```
Руслан до готовности модуля работает на заглушке с тем же интерфейсом (тестовый файл `tests/fake_mcp.py`).

## Правила безопасности (минимум, нарушать нельзя)
1. Белый список из двух инструментов в трёх местах: флаг `--tools`, клиент, тест. Любой `create_/send_/cancel_/delete_/update_/record_/pay_/refund` в списке роняет тест.
2. Только Sandbox; токен через окружение процесса; версии `@paypal/mcp` и `@paypal/agent-toolkit` закреплены lockfile (`npm ci`, не `npx -y`).
3. Результаты инструментов недоверенные: в модель идёт минимум (маска почты и телефона, усечение), инструкции из них не исполняются.
4. Не более 3 шагов агента на вопрос и общий таймаут; при отказе MCP или модели чат отвечает без инструментов, а не ошибкой.

## Факты, на которые опираемся (проверены по исходникам пакетов 2026-11-01, не запускались)
- `@paypal/mcp@1.8.1`: `--tools=invoices.list,invoices.get`, токен через `PAYPAL_ACCESS_TOKEN`, `PAYPAL_ENVIRONMENT` (по умолчанию Sandbox), stdio, Node >= 18. Ключей клиента сервер не принимает, только готовый токен.
- `list_invoices`: только `page`, `page_size` (до 100), `total_required`, **без фильтров по дате и статусу**; возвращает сырой JSON. `get_invoice`: `invoice_id`, сырой JSON с адресами, почтами, телефонами и примечанием.
- Бесплатные модели с `tools`: 13, в том числе все три из текущей цепочки. Работает ли вызов инструментов на практике, неизвестно (первая проверка в блоке 1).
- Формат: модель возвращает `tool_calls[].function.arguments` строкой JSON (разобрать и проверить по схеме), результат отдаётся сообщением `{"role":"tool","tool_call_id":…,"content":…}`.
- Toolkit видит только счета, **выставленные** подключённым аккаунтом; путь плательщика он не заменяет. Так и писать в описании.

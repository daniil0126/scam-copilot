# 06. Cross-Invoice Intelligence и история поставщиков

**Приоритет:** P1 (история поставщиков и дубликаты), P2 (связи между отправителями). **Разделы ТЗ:** 5, 15.9. **Зависит от:** 03, 04.

## Цель
Находить закономерности между инвойсами одного аккаунта и вести профиль поставщика.

## Задачи
- [ ] **Vendor history.** По отправителю: число инвойсов, сумма, среднее, последняя активность, история изменений email/имени/контактов, число подозрительных инвойсов. Обновляется при каждом анализе (таблица `vendors` + события изменений).
- [ ] Сравнение нового инвойса с профилем поставщика (питает правила A, C, E из плана 04).
- [ ] **Duplicate patterns.** Группы копий (кластеры), похожие инвойсы с изменённым номером/ID, повторяющиеся суммы и позиции. Сходство позиций через нормализацию текста, без AI.
- [ ] **Suspicious relationships (P2).** Общие подозрительные URL, совпадающие контакты, повторяющиеся шаблоны описаний между разными отправителями. Связь заявляется только при двух и более независимых совпадениях; один слабый признак даёт максимум «наблюдение».
- [ ] Каждая найденная закономерность хранит список конкретных доказательств (ID инвойсов и совпавшие значения).
- [ ] Пересчёт связей инкрементально, не по всей базе на каждый инвойс.

## Тесты
Кластер из 3 копий, один отправитель со сменой домена, два отправителя с одним URL (наблюдение), два с URL+телефон (связь), мало истории.

## Готово, когда
Профиль поставщика отображается с реальными данными, дубликаты группируются, слабые совпадения не превращаются в утверждения.

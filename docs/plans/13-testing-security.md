# 13. Тестирование, безопасность, надёжность

**Приоритет:** сквозной (пишется вместе с каждым планом, итоговая калибровка в конце). **Разделы ТЗ:** 10, 11, 15.8.

## Тестовый набор и метрики
Задачи ROADMAP 3.1–3.3 (20 текстов, `scripts/evaluate.py`, таблица в README) это тот же набор: ведём здесь, скрипт один. Демо-счета (ROADMAP 8.3) входят в живой прогон, `scripts/scenarios.py` и `/paypal/sandbox/invoices` используются для создания данных.
- [x] Синтетический набор `backend/tests/dataset/`: 20–30 нормальных, 10–15 подозрительных, дубликаты, смена данных поставщика, необычные суммы, случаи с недостатком данных. У каждого ожидаемая классификация и описание сценария. (Сделано: 59 кейсов в `cases.json` — normal 28, suspicious 13, supplier_change 6, insufficient_data 5, duplicate 4, unusual_amount 3.)
- [x] Скрипт оценки считает **Precision, Recall, False Positive Rate** на реальном прогоне, цифры не хардкодятся. (`backend/scripts/evaluate.py`; сами цифры ещё нигде не записаны.)
- [ ] По результатам калибровка порогов 05 и правил 04, итог записывается в отчёт (`docs/plans/calibration.md`).
- [ ] Граничные случаи: отсутствующие поля, некорректные данные, ошибки API, повторяющиеся ID, необычные валюты, сбои AI, prompt injection. Частично: сбои AI и prompt injection покрыты (`test_llm_injection.py`), остальное не сведено в один список.

## Безопасность
- [ ] OAuth 2.0, Client Secret только на backend, токены зашифрованы в БД, не в `chrome.storage`.
- [ ] Авторизация каждого запроса, изоляция данных по `account_id` (тест на доступ к чужому аккаунту).
- [ ] Валидация входных данных и ограничение размеров. Размеры текста ограничены; `invoice_id` не проверяется шаблоном (см. `security-checklist.md`, п. 4).
- [x] Безопасная обработка URL: разбор без перехода, без fetch по ссылкам инвойса (защита от SSRF).
- [x] Верификация подписи webhook (если используются).
- [x] Секреты и токены не попадают в логи; проверка grep по логам в тесте. (`security.install_log_scrubber()` вызывается в `main.py`; тесты проверяют чистильщик, не реальные логи приложения.)
- [x] Минимизация ПД в запросах к AI (см. план 07).
- [ ] Аудит-лог действий (подключение, пауза, ручной sync, смена порогов). Записываются смена порогов и создание отчёта; pause, resume, sync в `monitor.py` не пишут (Даниил).
- [x] Никаких автоплатежей, отмен и изменений инвойсов: тест, что в коде нет таких вызовов PayPal. (`test_security.py`; два sandbox-маршрута создания счетов остаются, решение команды.)

## Надёжность
- [ ] Retry/backoff, восстановление синхронизации, идемпотентность проверяются тестами планов 08–10.
- [ ] CI-команды: `pytest`, `npx tsc -b`, `eslint`.

## Готово, когда
Метрики посчитаны и записаны, все пункты критериев готовности (раздел 13 и Definition of Done раздела 15) подтверждены тестами или ручной проверкой.

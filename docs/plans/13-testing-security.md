# 13. Тестирование, безопасность, надёжность

**Приоритет:** сквозной (пишется вместе с каждым планом, итоговая калибровка в конце). **Разделы ТЗ:** 10, 11, 15.8.

## Тестовый набор и метрики
- [ ] Синтетический набор `backend/tests/dataset/`: 20–30 нормальных, 10–15 подозрительных, дубликаты, смена данных поставщика, необычные суммы, случаи с недостатком данных. У каждого ожидаемая классификация и описание сценария.
- [ ] Скрипт оценки считает **Precision, Recall, False Positive Rate** на реальном прогоне, цифры не хардкодятся.
- [ ] По результатам калибровка порогов 05 и правил 04, итог записывается в отчёт (`docs/plans/calibration.md`).
- [ ] Граничные случаи: отсутствующие поля, некорректные данные, ошибки API, повторяющиеся ID, необычные валюты, сбои AI, prompt injection.

## Безопасность
- [ ] OAuth 2.0, Client Secret только на backend, токены зашифрованы в БД, не в `chrome.storage`.
- [ ] Авторизация каждого запроса, изоляция данных по `account_id` (тест на доступ к чужому аккаунту).
- [ ] Валидация входных данных и ограничение размеров.
- [ ] Безопасная обработка URL: разбор без перехода, без fetch по ссылкам инвойса (защита от SSRF).
- [ ] Верификация подписи webhook (если используются).
- [ ] Секреты и токены не попадают в логи; проверка grep по логам в тесте.
- [ ] Минимизация ПД в запросах к AI (см. план 07).
- [ ] Аудит-лог действий (подключение, пауза, ручной sync, смена порогов).
- [ ] Никаких автоплатежей, отмен и изменений инвойсов: тест, что в коде нет таких вызовов PayPal.

## Надёжность
- [ ] Retry/backoff, восстановление синхронизации, идемпотентность проверяются тестами планов 08–10.
- [ ] CI-команды: `pytest`, `npx tsc -b`, `eslint`.

## Готово, когда
Метрики посчитаны и записаны, все пункты критериев готовности (раздел 13 и Definition of Done раздела 15) подтверждены тестами или ручной проверкой.

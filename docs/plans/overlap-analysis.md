## 4. Противоречия с существующим поведением, нужны решения

1. **Перезапись результата.** `Check.result` обновляется при повторной проверке; ТЗ требует хранить историю. Решение: новые таблицы `invoice_versions` и `analyses` (контракт уже описывает), старая `checks` остаётся для standalone и legacy.
2. **Три уровня против четырёх.** Старый экран на `low/medium/high`, новые на 4 (Q6).
3. **AI может только поднять уровень** (`apply_analysis`). Это совпадает с принципом ТЗ «AI не меняет score», но нужно решить, остаётся ли подъём уровня, или AI становится только пояснением (по ТЗ: `source=AI` у сигнала допустим, score определяет Rule Engine). Предложение: AI-находки отображаются, но в score не входят.
4. **Мёртвый код и моки** (`BrowserMock`, `PayPalDemoModal`, `UploadCard` и др.) не должны попасть в Batch Audit и в видео (ROADMAP 6.3).

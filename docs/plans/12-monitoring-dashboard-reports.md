# 12. Monitoring Dashboard и Monthly Intelligence Report

**Приоритет:** P2. **Разделы ТЗ:** 15.5, 15.6. **Зависит от:** 06, 09, 10.

## Цель
Обзор состояния мониторинга и ежемесячный отчёт, целиком посчитанные из сохранённых результатов.

## Monitoring Dashboard
- [ ] Статус мониторинга, время последней успешной синхронизации, всего инвойсов под мониторингом.
- [ ] Счётчики High, Critical, Potential Duplicates, Vendor Anomalies; лента последних событий обнаружения.
- [ ] Управление: Pause / Resume, ручной Sync, настройка порогов алертов, список ошибок синхронизации, переход к карточке инвойса.
- [ ] Список уведомлений (план 10) в этом же разделе.

## Monthly Report
- [ ] Выбор месяца; `POST /reports/monthly` сохраняет отчёт в `audit_reports` с версией и временем.
- [ ] Содержимое: всего проанализировано, распределение по уровням, дубликаты, аномалии поставщиков, подозрительные ссылки, чаще всего отмеченные поставщики, тренд риска по неделям, инвойсы для ручной проверки.
- [ ] Все числа считаются SQL-запросами по `analyses`; пустой месяц показывает пустое состояние, не нули-заглушки.
- [ ] Явная формулировка: «обнаруженные подозрительные признаки», а не «подтверждённое мошенничество».
- [ ] Экспорт отчёта (CSV или печатная версия) по необходимости.

## Тесты
Фикстура с известным набором анализов, ожидаемые агрегаты сверены вручную; месяц без данных; отчёт одного аккаунта не содержит данных другого.

## Готово, когда
Дашборд отражает реальное состояние backend, отчёт воспроизводим из БД.

# 04. Rule Engine

**Приоритет:** P0. **Раздел ТЗ:** 4. **Зависит от:** 03.

## Цель
Независимый от AI модуль правил. Принимает нормализованный инвойс и контекст истории, возвращает список сигналов.

## Контракт сигнала
`type, severity, evidence (конкретные значения), source (API | RULE_ENGINE | AI), rule_version`. Сигнал без evidence не создаётся.

## Уже есть в `scoring.py` (перенести в сигналы, не писать заново)
Новый поставщик, смена платёжного email (+60), смена имени при том же PayPal (+40), сумма против **одного** предыдущего инвойса, крупная сумма от нового отправителя, телефон в тексте, scam-слова, бренд при чужом домене, срок оплаты, наличие ссылки в заметке. 15 тестов в `test_scoring.py` должны остаться зелёными: сначала обёртка с теми же результатами, потом улучшения. Типы сигналов для них уже в `contracts.md`.

## Правила
- [ ] **A. Unusual Amount** (частично есть: сравнение с одним прошлым инвойсом). Сравнение с историей того же отправителя (среднее/медиана, разброс). Порог минимальной истории (например 3 инвойса, конфигурируемо), иначе статус `INSUFFICIENT_DATA`. Рост сам по себе не улика.
- [ ] **B. Duplicate** (первая версия: по одному аккаунту). Exact / Potential / Similar по ID, номеру, отправителю, сумме+валюте, позициям, близости дат. Совпадение одной суммы не даёт дубликат. Расширение в плане 06.
- [ ] **C. Vendor Impersonation** (частично есть: точное сравнение email и имени). Добавить похожие домены. Сравнение email/имени/контактов с историей: похожий домен, смена домена при том же имени и т.п. Только «несоответствие», не «мошенник».
- [ ] **D. Suspicious Link** (сейчас только факт наличия ссылки). Разбор URL без перехода: IP вместо домена, punycode, глубокие поддомены, бренд в чужом домене, несовпадение с ожидаемым `paypal.com`. Внешний URL сам по себе не вредоносен.
- [ ] **E. Unusual Sender Activity.** Частота и объём инвойсов отправителя относительно его истории; учитывать объём истории.
- [ ] Каждое правило возвращает `INSUFFICIENT_DATA` вместо молчаливого «ок».
- [ ] Правила конфигурируются (пороги в одном месте), версия набора правил записывается в анализ.

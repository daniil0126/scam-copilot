# 11. Batch Audit и Invoice Details (UI)

**Приоритет:** P1 (таблица), P2 (карточка, CSV). **Разделы ТЗ:** 8, 9. **Зависит от:** 05, 08.

## Цель
Раздел Batch Audit на AG Grid и подробная карточка инвойса, объясняющая «почему».

## Связь с существующим
`HistoryItem.tsx` уже на AG Grid Community: общий рендерер уровня риска (цвет и текст) и фильтры выносим в общий компонент для History и Batch Audit. Кнопка «Check all invoices» (ROADMAP 1.6 предлагал убрать) превращается во вход во вкладку Batch Audit. Сравнение с поставщиком в AG Grid (ROADMAP 4.2) переиспользуется в карточке инвойса. Задачи ROADMAP 4.x ведутся здесь.

## Задачи
- [ ] Новая вкладка в сайдпанели, использовать существующую архитектуру и AG Grid Community (как в `HistoryItem.tsx`); выбор периода запускает план 08.
- [ ] Колонки: Invoice ID, Number, Sender, Amount, Currency, Invoice Date, Risk Score, Risk Level, Signals, Analysis Status.
- [ ] Сортировка по Risk Score; фильтры: Risk Level, валюта, статус; поиск по ID и отправителю.
- [ ] Сводка: Total, Low, Medium, High, Critical, Unanalyzed.
- [ ] Состояния: Loading, Empty, API Error, Partial Results, Analysis Failed. Ошибка одного инвойса отмечается в строке, интерфейс не блокируется.
- [ ] **Карточка:** основные данные, score, level, confidence, все сигналы с evidence, исторические сравнения, рекомендации, AI-объяснение (с пометкой источника каждого сигнала).
- [ ] **CSV Export** из реальных данных таблицы (с учётом фильтров), экранирование формул (`=`, `+`, `-`, `@`).
- [ ] Никаких захардкоженных или демо-результатов в продакшн-интерфейсе.

## Тесты
Компонентные тесты состояний, проверка экспорта CSV, `npx tsc -b`, ручная проверка в браузере.

## Готово, когда
Аудит из плана 08 виден в таблице, из строки открывается карточка, CSV соответствует отфильтрованным данным.

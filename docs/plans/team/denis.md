## Правила интерфейса
- Формулировки «обнаружены признаки», «требует проверки», не «мошенник».
- Нет захардкоженных результатов, выдаваемых за реальные.
- Проверки: `npx tsc -b`, `eslint`, ручной прогон в Chrome.

## Готово, когда
Аудит из реального backend виден в таблице, строка открывает карточку, CSV совпадает с отфильтрованными данными.

## Снято с Дениса (2026-10-31, на время его отсутствия)
Часть «проверить письмо» делает Даниил, а не Денис. Решение принято тимлидом, потому что Денис сейчас не может работать. Что именно переходит:
- content script: сообщение `GET_PAYPAL_EMAIL` (читает письмо PayPal со страницы Sandbox notifications в Developer Dashboard, только по нажатию кнопки);
- `postInboundEmail(html)` в `src/api/client.ts` (запрос из боковой панели, не из content script: CORS бэкенда разрешает только origin расширения);
- кнопка «Check this email» рядом с «Check this PayPal invoice», результат берётся из поля `check` ответа `POST /inbound/email` (формат `VerificationResult`, тот же экран результата);
- поле «Inbound secret» в настройках (`chrome.storage.local`, не в коде и не в логах), тип `InboundEmailResponse` и dev-фикстура в `src/api/__fixtures__/`.

Сделано 2026-10-31 (не закоммичено): кнопка, секрет, чтение письма, `SourceBar` (что проверено и по какому источнику), `FindingsList` по группам и `ComparisonTable` по основаниям (логика в `src/lib/groupResult.ts`). Экран результата теперь общий для писем, страницы и API; Денису при возвращении: `Finding.detail`/`skipped` необязательны, старые результаты из History показываются без них.

Остальные задачи Дениса (Batch Audit, карточка инвойса, CSV, дашборд, отчёт) не затронуты. Когда Денис вернётся, он принимает сделанное как есть или переделывает по своим правилам интерфейса. Контракт: `POST /inbound/email` в [../contracts.md](../contracts.md), раздел 5.

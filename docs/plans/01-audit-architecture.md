# 01. Аудит и архитектура

**Приоритет:** P0, гейт для всего остального. **Разделы ТЗ:** 1, 2, 14.

## Цель
Понять, что уже есть, и сопоставить с ТЗ до написания кода. Ничего не переписывать без причины.

## Задачи
- [ ] Карта текущего стека: `backend/app/` (`main.py`, `paypal.py`, `checks.py`, `scoring.py`, `llm.py`, `chat.py`, `db.py`, `models.py`), `src/` (sidepanel, content script, `api/client.ts`), тесты в `backend/tests/`.
- [ ] Зафиксировать существующий парсер страницы PayPal (должен остаться рабочим) и что он отдаёт (`to_invoice()`).
- [ ] Список существующих эндпоинтов и моделей БД; что можно переиспользовать (`scoring.py` как основа для 05, `llm.py` для 07, AG Grid в History для 11).
- [ ] Таблица «ТЗ → есть / частично / нет» по каждому подплану.
- [ ] Проверка документации PayPal: методы Invoicing API, scope, пагинация, rate limits, webhooks, тип токена (см. конфликты в 00-ROADMAP).
- [ ] Решения по конфликтам из 00-ROADMAP, записать как ADR в `docs/plans/adr/` (по одному короткому файлу).
- [ ] Уточнить статус незакоммиченных изменений (много `M` в git status), чтобы не потерять работу.

## Результат
Файл `docs/plans/audit.md`: карта архитектуры, gap-таблица, список решений.

## Готово, когда
Для каждого подплана 02–13 определены файлы, которые меняются, и нет неразрешённых вопросов по API.

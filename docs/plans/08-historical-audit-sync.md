# 08. Historical Audit и инкрементальная синхронизация

**Приоритет:** P0. **Разделы ТЗ:** 15.1, 15.2 (ядро), 15.9 P0. **Зависит от:** 02, 03, 05.

## Цель
Пользователь выбирает период, система импортирует, анализирует и сохраняет инвойсы, не обрабатывая повторно неизменённые.

## Задачи
- [ ] `POST /audits` с периодом: 7 / 30 / 90 дней или custom range; возвращает `audit_id`, работа идёт в фоне.
- [ ] Загрузка инвойсов с пагинацией (план 02), фильтрация по дате.
- [ ] Для каждого: нормализация, хеш содержимого, проверка «эта версия уже обработана?». Новые/изменённые идут в очередь, неизменённые пропускаются.
- [ ] Анализ: Rule Engine, затем cross-invoice (план 06), затем score (05). Результаты в `analyses` с версией и временем.
- [ ] Изменённый инвойс создаёт новую версию и переоценивается; прежние результаты сохраняются.
- [ ] Повторный аудит не затирает прошлые отчёты: новая запись `audit_reports`.
- [ ] Статус аудита: прогресс (всего/готово/ошибки), partial results, ошибка одного инвойса не прерывает остальные.
- [ ] **Инкрементальная синхронизация:** чекпоинт «последняя успешная синхронизация» на аккаунт; следующий запуск берёт `updated since checkpoint` с небольшим перекрытием; чекпоинт двигается только после успешной записи.
- [ ] Ручной запуск синхронизации как запасной путь, лог в `sync_logs`.

## Тесты
Повторный импорт того же периода (0 новых заданий), изменённый инвойс (новая версия), падение на одном инвойсе, обрыв посреди пагинации и возобновление.

## Готово, когда
Аудит за 30 дней на Sandbox даёт сохранённые результаты, повтор ничего не дублирует, прошлые результаты остаются в истории.

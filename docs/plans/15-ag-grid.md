# 15. AG Grid: настоящее использование таблиц (ТЗ)

**Зачем.** Спонсорский приз «Best Use of AG Grid» (1-е место $5 000, 2-е $2 000, три по $1 000) получают работы, которые «use any AG Grid tools». Критерии для спонсорских призов в правилах не расписаны, поэтому ориентируемся на смысл названия: глубина использования, а не факт подключения. Сейчас это слабое место: сетка стоит только в History и работает как список карточек (`headerHeight={0}`, поиск, фильтры и сортировка сделаны в React вне сетки, у колонок нет `field`, нет сортировки и фильтров). Жюри увидит в видео «обычный список». Цель: сетка делает то, ради чего её берут, в четырёх местах продукта, и это видно за 15–20 секунд видео.

**Исполнитель:** Денис (`src/`). Пока он недоступен, зона разрешена Даниилу. **Срок:** готово к полудню 03.11, заморозка кода вечером 03.11. Коммиты только заголовком, без описания и подписей.

## Границы (нарушать нельзя)
1. **Только Community** (`ag-grid-community`, `ag-grid-react`, версия 36.x как в `package.json`). `ag-grid-enterprise` не подключать: без лицензии он рисует водяной знак и пишет в консоль, а лицензии у нас нет. Возможности Enterprise (группировка строк, master/detail, Set Filter, панели, интегрированные графики, экспорт в Excel, серверная модель) не использовать и не называть в описании.
2. **Никаких выдуманных данных.** Колонки показывают то, что вернул бэкенд; нет значения: «—». Фикстуры только в `src/api/__fixtures__/` и в прод-сборку не попадают.
3. **Формулировки «признаки», не «мошенничество».**
4. Секреты (`Inbound secret`) в состояние колонок и в экспорт не попадают.
5. Не менять контракт API: все поля уже есть (`HistoryEntry`, `AppNotification`, `MonitoringEvent`, `FullReport` в `src/api/types.ts`). Нужно поле, которого нет: сначала Даниилу.
6. Сборка не должна ломаться: `npx tsc -b`, `npm run build`, `npx eslint .` (известные ошибки типов `chrome` в старом коде не считаем).

## Общая основа (делать первой, `src/components/grid/`)
| Файл | Что внутри |
|---|---|
| `gridSetup.ts` | `ModuleRegistry.registerModules(...)` один раз на приложение. Нужные модули Community (клиентская модель строк, сортировка, фильтры текста/чисел/дат, быстрый фильтр, пагинация или виртуализация, CSV, стили ячеек и строк, тултипы, выбор строк, автоподбор ширины, перетаскивание и скрытие колонок) или `AllCommunityModule`, если вес сборки приемлем. Имена модулей сверить с документацией 36. Сейчас регистрируется только `ClientSideRowModelModule`: без остальных фильтры и сортировка не заработают. |
| `gridTheme.ts` | `themeQuartz` + `colorSchemeLight/Dark`, параметры из CSS-переменных проекта (`--card`, `--border`, `--text`, `--primary`), компактная плотность. Одна тема для всех таблиц; смена `settings.theme` меняет тему. |
| `cells.tsx` | Общие рендереры: `RiskBadgeCell` (иконка + подпись, цвет не единственный носитель смысла: `LEVEL_META`), `MoneyCell`/`valueFormatter` (через `formatMoney`, неизвестный код валюты не роняет, как сейчас), `DateCell` (ISO в значении, локальная строка в отображении), `SignalsCell` (до 2 признаков + «+N», читаемые названия через `signalLabel`), `UnreadDotCell`. |
| `GridToolbar.tsx` | Поле быстрого фильтра (`quickFilterText`), кнопка «Export CSV», «Reset columns», счётчик «N of M». Подписи для скринридера. |
| `useGridPrefs.ts` | Сохранение состояния колонок (порядок, ширина, скрытие, сортировка, фильтры) в `chrome.storage.local` под ключами `grid:<имя>:v1`; чтение при старте, запись с задержкой при изменении; вне расширения (`npm run dev`) тихо ничего не делает; повреждённое значение игнорируется. |
| `localeText` | Англоязычные подписи фильтров и меню (по умолчанию уже английские; проверить, что нет польских строк: в `HistoryItem.tsx` есть польские комментарии, их перевести на английский). |

Общие требования ко всем сеткам: `getRowId` по стабильному ключу; состояния «загрузка», «пусто» (понятное сообщение, не пустая сетка), «ошибка» (как сейчас в других вкладках); не отключать фокус ячеек (`suppressCellFocus` убрать), Enter или пробел на строке открывает её; `prefers-reduced-motion` отключает анимации и мигание; высота сетки от контейнера (flex), а не фиксированные 365px; адаптивность: в боковой панели 360–480 px видны уровень, поставщик, сумма, при ширине больше ~640 px добавляются остальные колонки (скрытие колонок по ширине контейнера через `ResizeObserver`).

## Таблица 1. History (`HistoryItem.tsx`), переписать как настоящую сетку
Данные: `HistoryEntry[]` (поиск и фильтры, сделанные вручную в React, переносим в сетку).
- Колонки: Level (`RiskBadgeCell`, сортировка по порядку high > medium > low, фильтр), Supplier, Invoice № (`invoice.number`, если есть), Amount (числовая колонка, выравнивание вправо, сортировка по числу, числовой фильтр), Currency (в составе суммы, отдельным фильтром не нужна), Due, Checked at (сортировка по умолчанию: новее выше), Source (`page` / `email` / `api` из `CheckSource`, если поле есть), Signs (`SignalsCell`).
- Быстрый фильтр вместо ручного поля поиска; меню «Filters» с чекбоксами уровней заменить на фильтр колонки Level или на плавающие фильтры.
- Закрепить слева Level, справа стрелку открытия; клик по строке или Enter открывает проверку, как сейчас (`onOpen(id)`).
- Статистика сверху («Invoices checked», «High risk», «Flagged amount») считается от **отфильтрованных** строк (`onFilterChanged` / `forEachNodeAfterFilter`), и это видно: фильтруешь, плитки меняются.
- Подсветка строки: `rowClassRules` для high (мягкий фон) без потери читаемости в тёмной теме.
- Экспорт CSV: только видимые колонки и отфильтрованные строки, без внутренних ID проверки; имя файла `scam-copilot-history-YYYY-MM-DD.csv`. Осторожность с CSV-инъекцией: значения, начинающиеся с `=`, `+`, `-`, `@`, экранировать (`processCellCallback`), потому что поставщик и примечания приходят от посторонних.
- Сохранение состояния колонок (`useGridPrefs("history")`).
- Режим «Compact / Table»: в узкой панели по умолчанию компактный (3 колонки), в широком таблица. Если времени мало, один адаптивный режим.

## Таблица 2. Alerts (`AlertsView.tsx`)
Данные: `AppNotification[]`; курсорная подгрузка (`nextCursor`, «Load more») остаётся: новые страницы добавляются через `applyTransaction({ add })`, а не пересборкой массива.
- Колонки: Unread (точка), Level (`AlertLevel`), Type (читаемое название `AlertEventType`), Supplier, Invoice №, Amount, Due, Detected at.
- Непрочитанные: `rowClassRules` (жирный шрифт), быстрый фильтр, фильтр по типу и уровню; переключатель «Unread only» остаётся, но работает как фильтр сетки или запрос бэкенда (как сейчас).
- Клик по строке: пометить прочитанной (как сейчас, с откатом при ошибке: обновить строку через `applyTransaction({ update })`) и показать детали под таблицей (признаки, сообщение, кнопка «Open this check»). Дублировать логику `open` не нужно, использовать существующую.
- Бейдж непрочитанных в табе не должен ломаться.

## Таблица 3. Monitor, последние события (`MonitoringCard.tsx`, `recentEvents`)
Данные: `MonitoringEvent[]`, бэкенд опрашивается каждые 10 с (`useMonitoring`).
- Колонки: Event (`NEW_INVOICE` / `INVOICE_UPDATED`), Detected at, Supplier, Invoice №, Amount (в `amount` строка: парсить в число для сортировки), Status, Risk, Signs.
- **Живое обновление:** новые события добавляются через `applyTransaction({ add, addIndex: 0 })` с `getRowId` по `invoiceId + detectedAt`, изменённые обновляются, новые строки мигают (`flashCells` / `enableCellChangeFlash`) и сохраняется существующая подсветка «new» по `highlightSince`. Это главный кадр для видео: создал счёт, через несколько секунд строка появилась сама.
- Не показывать «полную страницу» сетки внутри свёрнутой карточки: сейчас показывается 4 события и «show all». Сетка высотой на ~6 строк с прокруткой и фильтром по риску.

## Таблица 4. Monthly report (`MonthlyReportView.tsx`)
Данные: `FullReport.manualReview` («Worth a manual look»), `topFlaggedSuppliers`, `weeklyTrend`.
- `manualReview`: Level, Supplier, Invoice №, Amount, Due, Score (`riskScore`, ячейка с горизонтальной полосой), Signs; кнопка/ячейка «Open check» по `checkId`, если он есть.
- `topFlaggedSuppliers`: Supplier (имя или email), Flagged invoices (полоса).
- `weeklyTrend` оставить как есть (CSS) или заменить на AG Charts (см. ниже).
- Экспорт CSV этих таблиц рядом с кнопкой сохранения отчёта.

## Критерии готовности
- [ ] History, Alerts, Monitor events, report-таблицы работают на сетке со своими `field`, сортировкой, фильтрами, быстрым фильтром, пользовательскими рендерерами; ручной поиск и сортировка в React удалены.
- [ ] Monitor добавляет и обновляет строки через `applyTransaction`, мигание видно, при `prefers-reduced-motion` его нет.
- [ ] Состояние колонок сохраняется между открытиями панели и сбрасывается кнопкой.
- [ ] CSV экспортирует видимое, экранирует опасные значения.
- [ ] Светлая и тёмная тема, ширины 360 / 480 / 900 px: нет обрезанных заголовков, горизонтальная прокрутка не мешает, строки не прыгают.
- [ ] Клавиатура: Tab доходит до сетки, стрелки двигают фокус, Enter открывает строку; у кнопок и фильтров есть подписи.
- [ ] Пустые, загружаемые и ошибочные состояния; строка без суммы, без поставщика, с неизвестной валютой не ломает сетку.
- [ ] 500 и более строк в History не тормозят (проверить на синтетическом наборе в dev-режиме, не в прод-данных).
- [ ] Консоль без предупреждений AG Grid (особенно про незарегистрированные модули и про Enterprise); `npx tsc -b`, `npm run build` чисто; размер `dist/assets` не вырос неоправданно (записать до и после).
- [ ] Проверено вручную в живом Chrome (Load unpacked `dist/`), с бэкендом и данными из `scenarios.py` и `POST /monitoring/sync`.
- [ ] Абзац для Devpost и README: что именно используется (список функций Community из фактической реализации, не из этого документа) и честно «Community edition».

How it works

Three ways in. One list of evidence out.

01

The invoice page

Open the invoice PayPal shows you as the payer and press Check this PayPal invoice. PayPal’s API hides invoices issued by others, so this is how a stranger’s invoice gets checked.

02

Your own account

The backend reads the invoices of the connected PayPal account through the Invoicing API and watches them for changes, with webhooks where PayPal sends them.

03

The invoice email

Open the email in the Developer Dashboard and press Check this email. Scam Copilot checks where its links lead and what changed since the earlier email.

What it finds

Signs, not verdicts.

PAY-01

Payment email changed

The supplier’s PayPal email differs from the earlier invoices.

AMT-02

Amount far from usual

Compared with earlier checks of the same supplier.

ID-03

Same email, new name

A known PayPal address now appears under a different business name.

TXT-04

Phone number or scam wording

“Call to cancel” notes are the classic refund-scam hook.

BRD-05

Known brand, unrelated name

A famous product name sold by a business that is not it.

CHG-06

Changed after sending

The update email leaves the note out; the payer page shows it. The difference is flagged.

Every finding carries its evidence. One serious red flag never produces a low score. Missing data stays empty instead of being guessed.

Built to be trusted

A model explains. Rules decide.

Rules set the score

Each finding adds points; the total maps to low, medium or high. An optional language model can write the explanation and answer questions in the chat. It never changes the score, and anything in its answer that is not in the invoice is dropped.

Your data stays narrow

The content script runs only on paypal.com. Invoice text reaches the model as data, never as instructions. Secrets are scrubbed from logs. The chat can read two things from PayPal, the invoice list and one invoice, and nothing else.

Honest limits

What a low score does not mean.

What works today

  • Payer pages, account invoices and invoice emails
  • History table of every check, and live monitoring with in-app alerts
  • A monthly report counted from stored checks

What does not, yet

  • Tested on PayPal Sandbox only, not on live accounts
  • Rules are tuned on demo scenarios, not on real fraud data
  • A low score is a heuristic, not a guarantee that an invoice is safe

Install

Running in about ten minutes.

  • Chrome
  • Node 20+
  • Python 3.11+
  • PayPal Developer account (free)

  1. Get the code

    git clone https://github.com/daniil0126/scam-copilot.git cd scam-copilot

  2. Create a PayPal Sandbox app

    In the PayPal Developer dashboard open Apps & Credentials, switch to Sandbox, create an app with the Invoicing feature on, and copy its Client ID and Secret. Use Sandbox only; never put live credentials in a demo.

  3. Start the backend

    cd backend python -m venv .venv && source .venv/bin/activate pip install -r requirements.txt cp .env.example .env uvicorn app.main:app --port 8000

    Before the last line, fill PAYPAL_CLIENT_ID and PAYPAL_CLIENT_SECRET in backend/.env. Then http://localhost:8000/health should answer {"status": "ok"}.

  4. Build the extension

    cd .. npm ci npm run build

  5. Load it in Chrome

    Open chrome://extensions, turn on Developer mode, press Load unpacked and choose the dist/ folder. Click the Scam Copilot icon to open the side panel.

  6. Check an invoice

    In the sandbox, send an invoice from a business account to a personal account and open it as the payer (sandbox.paypal.com/invoice/p/#…). Press Check this PayPal invoice in the side panel.

    To get demo invoices fast, run python scripts/scenarios.py --links in backend/.

Optional: LLM_PROVIDER, LLM_API_KEY and LLM_MODEL in .env turn on the AI review and the chat. Without them everything runs on the rules alone. Full setup, including webhooks and email checks, is in the README.
